## 一、发布模块数据结构透视（现状）

发布三入口 → 两个内容池，数据结构如下：

```
入口 A · 推荐好东西（沉浸式）      → 发现内容池 lib/discovery-store.ts
  输入：content（一段话，可含外链/#标签）
  写入 DiscoveryItem：
    { id, type: "内容", title: toTitle(text),        ← ⚠ 强制截断首行 24 字做"标题"
      description: text, note: text,                 ← ⚠ 两字段存同一段话（冗余）
      author: "我的账户", publishTime: "刚刚",
      views: 0, likes: 0, comments: 0,
      tags, url, kind }

入口 B · 推广外链（带分佣）        → 发现内容池
  同 A + { commercial: true, promoType, commission, url 必填 }

入口 C · 话题帖子                  → 广场话题池 lib/square-store.ts
  输入：content + 可选 url
  写入 SquarePost：{ id, author, content, tags, likes, comments, views, time, url }
```

## 二、「推荐好东西」内容结构的根本问题

你的示例内容揭示了问题的本质：

> 关键：集合里的元素一定是确定的（不能模棱两可，比如"高个子"就不是集合……）

**这是一段"正文"，不是"标题+摘要"**。随手写内容的真实形态就是一段话，而当前实现把它强制"标题化"：

| 问题 | 表现 |
|---|---|
| **强制标题** | `toTitle()` 截断首行 24 字当标题 → 卡片显示一个"半截话"当标题，语义断裂 |
| **字段冗余** | `description` 和 `note` 存的是同一段话（发布时），详情页"标题+推荐语"重复展示 |
| **结构错位** | 预置内容（编辑精选）是"标题+简介"结构；用户发布是"纯正文"结构——**两种形态没被数据模型区分** |

**核心结论：title 应该是"可选元信息"（编辑精选才有），正文（note）才是内容本体。随手写发布的内容 = 只有正文。**

## 三、改版方案

### 1. 数据结构修正（让两种形态并存且语义清晰）

```ts
DiscoveryItem {
  title?: string;        // 可选：编辑精选才有；随手写发布不设 → 卡片/详情页用正文兜底
  note: string;          // 正文（内容本体）——发布时用户写的一段话
  description?: string;  // 可选简介（预置内容有；发布内容不再重复写）
  // …其余字段不变
}
```

- 发布 A/B：`note = 正文`，**不再生成 title**，不再重复写 description；
- 预置内容：保留 title + description + note（三种都有，编辑精选形态）；
- 卡片/详情页取数规则统一：**有 title 用 title，无 title 用 note 开头**。

### 2. 卡片显示：社交化结构（头像 + 用户名 + 正文，发现页同步改 3 列）

- 网格：4 列 → **3 列** `repeat(auto-fill, minmax(240px, 1fr))`（中栏 868px 下 3 列 ≈ 280px/卡，宽 35%，正文 2 行放得下）；
- **卡片结构从「物件索引」改为「人的发布」**：

```
◯ 山岚 · 3 小时前                 ♡   ← 顶行：头像 + 用户名 + 时间 + 收藏
跟着做完了前几章，批量整理文件        ← 正文：note ?? description 前 2 行截断
的思路很实用，适合想提高效率…
#Python #自动化                     ← 标签（最多 2 个）
────── 细线 ──────
学习资源                        B 站   ← 底部统一行：类型 / 来源（推广卡显示 ⚠ 警示）
```

- 正文取数规则：`note ?? description`（用户发布的正文即 note；预置内容取推荐语）；
- 标题（title）不再出现在卡片——只在详情页作为大字标题（有则显示）；
- 有 `url` 的内容：来源显示来源平台名，点击详情页「前往原平台」回流；
- 推广卡：底部行右侧显示 ⚠ 警示（`promo-note` 保留），合规不变。

### 3. 详情页：流式结构（头像 → 正文 → 互动 → 行动）

按你指定的顺序重排：

```
← 返回发现
◯ 山川 · 10 分钟前 · 来自 开发者社区     ← ① 用户头（头像置顶）
[内容] [⚠推广]（标识小字）
正文全文（大字，note ?? title+description） ← ② 正文（媒体展示保留）
#标签
浏览 128 · 赞 24 · 评论 6               ← ③ 互动（社会证明）
[前往原平台 →] [去广场讨论]              ← ④ 行动（最后）
相关讨论 / 相关推荐（保留在末尾）         ← ⑤ 延伸
```

与现版的差异：**推荐者块从"中部灰卡"上移为"顶部用户头"；正文直接展示不再拆"推荐语+简介"两段；互动提前到行动之前**——更接近微博/朋友圈正文页，内容流式阅读，动作顺序自然。

### 4. 推广/媒体能力不受影响

- 推广标识、佣金警示、媒体展示（图片/视频/文档）都在新结构里原位保留；
- `url` 缺失时「前往原平台」按钮隐藏，其余不变。

## 四、可行性结论

**可行，且是纯前端改造（不碰后端冻结清单）**，改动集中在 5 个文件：

| 文件 | 改动 |
|---|---|
| `lib/types.ts` | title 改可选、note 提升为主字段语义（注释更新） |
| `lib/data.ts` | 预置内容数据结构不动（本就符合新模型） |
| `components/app/shell/publish-modal.tsx` | A/B 提交：不再 toTitle、不再重复 description |
| `components/app/discovery/discovery-card.tsx` | 正文区 = title ?? note 2 行截断；外链标记 |
| `app/(app)/discover/[id]/page.tsx` | 详情页结构重排（用户头→正文→互动→行动） |
| `styles/app/discovery.css` + `detail.css` | 3 列网格 + 正文行截断 + 用户头样式 |

工作量：**0.5-1 天**。风险点：`title` 改可选后需检索全库引用（`toTitle`、`RecommendItem` 继承）确保无强制依赖。
