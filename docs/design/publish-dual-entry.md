# 发布双入口（内容 / 推广外链）UI 设计方案

> 版本：v1.1 · 日期：2026-08-21 · 状态：**已被 v2.0 定稿取代（见 publish-quick-post.md）**
> 承接：docs/design/business-model-redesign.md（外溢展示层业务模型）

---

## 一、设计目标

发布是引力业务的核心入口，拆分为**两个业务入口**：

| 入口 | 定位 | 商业属性 |
|---|---|---|
| **发布内容** | 分享你发现的好东西（资源/教程/作品/博客） | 非商业，外链可选 |
| **推广外链（商业）** | 带佣金/返佣/付费的推广 | 商业，外链必填 + 商业声明必填 |

分离理由：两类业务**表单字段不同、规则不同、展示标注不同**——混在一个表单里会造成"推广声明"被普通用户忽略，或普通内容被迫填商业字段。入口分离让用户**先想清楚发什么，再进入对应表单**，商业内容天然走"透明声明"流程。

---

## 二、交互流（三步）

```
点击「+ 发布」
  → 弹窗 Step 1：类型选择（发布内容 / 推广外链）
      → 选择「发布内容」→ Step 2a 内容表单
      → 选择「推广外链」→ Step 2b 推广表单（带商业声明）
      → 任一步可「← 返回」回 Step 1
  → 提交 → mock 成功提示 → 关闭
```

```
│  [           发布推广               ]│
└──────────────────────────────────────┘
```

**表单差异对照**：

| 字段 | 内容表单 | 推广表单 |
|---|---|---|
| 外链链接 | 可选 | **必填**（无外链无法回流原平台） |
| 推广类型 | — | 必选（返佣/订阅分成/付费课程/积分活动） |
| 佣金说明 | — | **必填**（透明展示，商业标注依据） |
| 商业警示框 | — | 展示（accent 金色提示条） |
| 提交按钮 | 发布 | 发布推广 |

## 四、商业标注与警示（发布后生效）

1. **卡片标注**：商业内容类型标签旁带「推广」徽标（复用现有 `.app-tag.commercial` 金色样式）；
2. **佣金说明**：卡片底部灰字展示（如「分享得 30% 分佣」）；
3. **全站声明**：页脚免责 + 发布流程警示 + 未来详情页提示，统一文案：
   > 「引力只做展示与连接。含推广链接的内容，交易与交付在原平台完成，请自行判断。」

## 五、内容落点与数据流（发布到哪里）

**一句话：发布的内容进入「发现内容池」，展示在发现流（主落点），同时进入首页推荐候选、分类体系与「我的发布」管理。引力不托管内容，卡片点击跳原平台外链。**

```
+ 发布（弹窗双入口）
  ↓ 提交
内容池 discoveryItems（单一事实源，可追加）
  ├── 发现流 /discover   全量展示 + 类型/商业筛选（主落点）
  ├── 首页 /home         为你推荐候选
  ├── 分类 /categories   按类型自动入组
  └── 我的发布（settings）我发布的条目 · 已发布/已下架
```

**数据落点（mock 阶段）**：
- 内容池 = `lib/data.ts` 的 `discoveryItems`（唯一数据源）；
- 发布提交 → 前端把新条目**追加进内容池**（内存态）→ 发现流立即可见；
- 刷新后还原（无持久化）——这是 mock 阶段边界；接后端时内容池换 fetch，发布走真实 API；
- 可选增强：用 `localStorage` 做前端持久化（发布后刷新仍在），纯前端可实现，但引入存储副作用——**列为 P1 可选，本期不做**。

**区分「我的发布」**：内容条目带 `owner` 标记（如 `owner: "me" | "platform"`），「我的发布」管理页只列 `owner: "me"` 的条目，支持已发布/已下架状态（复用 settings-panel 发布管理雏形）。

**弹窗 vs 独立页**：发布为轻量动作（一条外链 + 描述），**弹窗合适**；「我的发布」管理放 settings 面板（已有雏形），未来量大了再独立页面。

## 六、实现落点（纯前端 mock，不碰后端冻结清单）

| 层 | 变更 |

| **交互** | 提交 mock 成功提示（复用 `.square-mock-note` 模式）；← 返回回 Step 1 |
