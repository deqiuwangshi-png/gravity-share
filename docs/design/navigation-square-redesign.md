> 版本：v1.1 · 日期：2026-08-21 · 状态：**✅ 已确认并实施**（四结构导航 / 三列卡片 / 广场模块已完成）
> 范围：侧边栏导航信息架构 / 广场（交流分享）新模块 / 发现页卡片布局

## 一、背景与目标

1. 发现页（/home）「为你发现」区域由两列改为**一行三列卡片**；
2. 侧边栏新增**「广场」**入口，定位交流分享；
3. 重新审视导航结构——「发现」与「推荐」疑似冲突，拟调整为 **首页 / 发现 / 分类 / 广场**。

本文先做分析，确认方案后再开发。

---

## 二、现状梳理

### 2.1 当前侧边栏导航（config.ts · EXPLORE_NAV）

```
探索
├── 发现 ⌂        /home        应用首页 = 发现页（公告 + 为你发现 + 右栏）
├── 推荐 ◉        /recommend   推荐页（推荐理由卡片）
└── 全部分类 ▦    /categories  分类浏览
+ 发布按钮（弹窗）
```

### 2.2 「发现」vs「推荐」现状对比（冲突证据）

| 维度 | 发现 /home | 推荐 /recommend |
|---|---|---|
| 数据 | `discoveryItems`（6 条） | `recommendItems`（6 条） |
| 数据同源性 | — | 6 条中 5 条与发现同主题（AI 工具、独立开发、3D 模型、Python、SaaS 案例） |
| 卡片 UI | `DiscoveryCard` | 同一 `DiscoveryCard`（多一行 reason） |
| 布局样式 | `.discovery-grid` 两列 | **`.recommend-grid` 无任何样式定义**（默认流式单列） |
| 个性化逻辑 | 无（静态 mock） | 无（reason 为写死文案，如「因为你看过：AI 编程工具合集」） |

**结论：存在明确冲突。** 两个入口数据同源、组件同卡、无真实个性化差异，用户感知上几乎是同一内容的两张脸，独立导航位价值低；且「首页 /home」与导航项「发现」本就是同一页，层级重复。

## 三、建议方案：四结构导航（首页 / 发现 / 分类 / 广场）

### 3.1 信息架构（职责矩阵）

| 导航项 | 路由 | 职责（唯一性） | 承载内容 |
|---|---|---|---|
| **首页** | `/home`（改造） | 聚合门户：看一眼今天有什么 | 公告走马灯 + **为你推荐**（三列，接管原推荐位）+ 热门发现（右栏）+ 快捷入口 |
| **发现** | `/discover`（新增） | 完整内容流：浏览全部好东西 | 全部发现（三列）+ 类型筛选 chips（复用 APP_CATEGORIES） |
| **分类** | `/categories`（保留） | 分类浏览 | 现状不变 |
| **广场** | `/square`（新增） | 站内交流：人对人的分享讨论 | 帖子流 + 发帖框（mock） |

### 3.2 路由变更

| 动作 | 路由 | 说明 |
|---|---|---|
| 改造 | `/home` | 由「发现页」改为「聚合首页」 |
| 新增 | `/discover` | 完整发现流（原 home 的内容职能迁移至此） |
| 新增 | `/square` | 广场（新模块） |
| 移除 | `/recommend` | 页面删除；`next.config.ts` 加 `redirects`：`/recommend → /home`，旧链接不 404 |

### 3.3 「推荐」的去向（不浪费，不占位）

推荐不删除产品价值，而是**降级为首页内的「为你推荐」区块**：
- 复用 `recommendItems`（含 reason），三列卡片展示在首页；
- 后续接后端时，该区块就是「个性化推荐位」的自然落点；
- 导航上不再单列「推荐」，消除冗余。

### 3.4 数据 / 组件 / 样式变更

| 层 | 变更 |
|---|---|
| lib/config.ts | `EXPLORE_NAV` 重组为 4 项：首页 ⌂ / 发现 ✦ / 分类 ▦ / 广场 ◈；组名「探索」→「导航」 |
| lib/data.ts | 新增 `squarePosts`（5-6 条 mock）；`discoveryItems` 由 6 条扩至 9 条（三列 3×3 铺满） |
| lib/types.ts | 新增 `SquarePost` |
| lib/icons.ts | 新增 `plaza: "◈"`（广场图标，复用现有符号） |
| 组件 | 新增 `app/(app)/square/page.tsx`、`app/(app)/discover/page.tsx`；帖子卡先内联（重复第二次再抽 `components/app/square-post.tsx`）；`DiscoveryCard` 不变 |
| 样式 | `discovery.css` 网格改三列 + 断点；新增 `styles/app/square.css` |

### 3.5 产品职责边界（防混淆）

- **发现 = 对「东西」的发现**：外链资源（工具/课程/作品…），发布入口 = 侧边栏「+ 发布」；
- **广场 = 对「人」的交流**：站内文字帖子（话题/分享/讨论），发帖入口 = 广场内输入框；
- 两者数据、卡片、发布链路完全分离，互不干扰。

## 四、发现页三列卡片方案

### 4.1 布局

```
discovery.css
.discovery-grid { grid-template-columns: repeat(3, 1fr); }   ← 默认三列
@media (max-width: 1100px) { repeat(2, 1fr); }               ← 平板两列（保留）
@media (max-width: 800px)  { 1fr; }                          ← 手机单列（保留）
```

### 4.2 窄列适配（三列下卡片 ≈ 280px 宽）

| 项 | 现值 | 建议 | 说明 |
|---|---|---|---|
| 卡片 padding | 20px | 18px | 窄列减少内衬 |
| 描述 min-height | 43px（两行） | 48px | 保持两行视觉节奏 |
| 标题字号 | 17px | 16px | 窄列收窄 |
| tags / 来源行 | 现状 | 不变 | 已在窄列友好 |

> 具体数值待实现后视觉走查微调；骨架不变。

## 五、广场模块设计（mock）

### 5.1 页面结构

```
/square
├── 页头：广场 · 交流与分享
├── 发帖框（占位）：输入内容 + 「发布」按钮（mock 提交 → 提示成功）
└── 帖子流（SquarePost 卡片）
    ├── 作者头像（首字）+ 昵称 + 时间
    ├── 帖子内容
    ├── 标签 chips
    └── 赞 / 评论（前端可点，mock 数字）
```

### 5.2 数据模型

```ts
interface SquarePost {
  author: string;
  content: string;
  tags: string[];
  likes: number;
  comments: number;
  time: string;
}
```

mock 5-6 条：如「发现了一个不错的 AI 工具集」「今天把收藏夹整理完了」「求推荐好用的设计资源站」…

### 5.3 复用与新增

- 右栏（AppAside）在广场页是否展示：建议**保留**（跨页布局一致，治理 V2 要求）；
- 帖子卡与 DiscoveryCard 结构差异大，不强行复用；先内联，出现两处再抽。
