> 版本：v2.0 · 日期：2026-08-21 · 状态：**✅ 已确认并实施**（含媒体展示 v2，见 discover-media-showcase.md）
> 承接：discover-5col.md（4 列紧凑卡 + 详情页）、business-model-redesign.md（外溢展示层业务模型）

## 一、问题复盘：第一性原理回看

用户反馈：「点进发现卡片，详情页很空旷，内容很少，不知道这个东西是不是真的。」

**第一性原理拆解**：

- 平台本质：**分享与推荐平台**——核心动作是"一个人把好东西推荐给陌生人"；
- 平台使命：**打破生态孤岛**——让任何平台的好东西流动到陌生需求者面前；
- 详情页本质任务：**帮用户决策"要不要点出去看原平台"**。

当前详情页只有「类型 + 标题 + 简介 + 来源 + 按钮」——它回答了"是什么"，但没有回答另外两个更关键的问题：

| 用户进入详情页心里的问题 | 当前页面 | 缺口 |
|---|---|---|
| 这是什么？ | ✅ 标题 + 简介 | — |
| **谁推荐的？可信吗？** | ❌ 只有一个"推荐自：xxx"小字 | 无推荐人、无推荐语、无时间 |
| **别人怎么看？** | ❌ 什么都没有 | 无浏览/赞/评论、无相关讨论 |

**空旷感的根源**：页面没有"人"和"人的反馈"，只有一张放大的卡片。而推荐平台最值钱的恰恰是**人（推荐者）**和**人的反馈（社会证明）**。

## 二、改版方向：推荐决策页（单栏，套用 V2 阅读页例外条款）

```
← 返回发现

[类型] [⚠推广]                    ← 标识区
标题（大）

┌──────────────────────────────┐
│ 推荐语：整理当前值得尝试的 AI   │  ← ① 推荐者块（核心新增）
│ 编程工具，都是我实际用下来觉得   │     （人话 + 信任）
│ 值得的。                       │
│ ◯ 山川 · 10 分钟前 · 来自 开发者社区 │
└──────────────────────────────┘

┌──────────────────────────────┐
│ 内容简介                      │  ← ② 内容本体
│ 从代码生成到 Agent 开发……      │     （这个东西到底是什么）
│ #AI  #编程  #开发者            │
└──────────────────────────────┘

[前往原平台 →]  [去广场讨论]        ← ③ 行动区（双出口）

浏览 128 · 赞 24 · 评论 6          ← ④ 社会证明（热度）

相关讨论 · 广场上的人怎么说          ← ⑤ 相关讨论（2-3 条）
  ▸ 有人用过这家的 Agent 功能吗？…    （别人真实评价）

相关推荐 · 同类内容（3-4 条小卡）    ← ⑥ 延伸浏览
```

### 六个区块职责

| 区块 | 内容 | 回答的问题 |
|---|---|---|
| ① 推荐者块 | 推荐语（发布者原话）+ 头像 + 昵称 + 发布时间 + 来源平台 | **谁推荐的？为什么？** |
| ② 内容本体 | 内容简介 + 标签 + （推广卡的佣金/风险说明） | 这是什么？ |
| ③ 行动区 | 「前往原平台 →」（主）+「去广场讨论」（次） | 接下来去哪？ |
| ④ 社会证明 | 浏览 / 赞 / 评论 三格 | 别人觉得值不值？ |
| ⑤ 相关讨论 | 广场上提到此内容/同主题的帖子 2-3 条 | 别人怎么说？ |
| ⑥ 相关推荐 | 同类型内容 3-4 条（复用 4 列小卡） | 还有没有类似的？ |

## 三、关键设计决策

### 1. 推荐语与内容简介分离（数据语义，信任核心）

- **推荐语（`note`）**＝发布者原话（"今天发现一款神级3D建模软件…"）——**平台的核心资产是人话**，详情页重点展示；
- **内容简介（`description`）**＝这个东西的事实描述（可选）；
- 现状问题：发布时用户写的正文被存成 `description`，语义混淆。改版后：
  - 发布入口 A/B 正文 → 存 `note`（推荐语）；
  - 预置 mock 数据补 `note`（模拟"有人推荐时说了什么"）；
  - 列表卡片展示保持现状（`title` + 一行摘要），详情页才展开推荐语——信息分层。

### 2. 推荐人信息（信任三要素之一）

- mock 阶段：昵称 + 首字头像（纯色圆）+ 相对时间 + 来源平台；
- 不引入图片头像体系（避免过度设计），首字头像用现有色板变量；
- 接后端后：真实用户体系 + 关注/主页入口。

### 3. 社会证明数据（信任三要素之二）

- `DiscoveryItem` 加 `views` / `likes` / `comments`（mock 数值）；
- 点赞可交互（±1，复用 square-actions 的交互模式——**用到两次即抽，暂不抽**，先各写各的）。

### 4. 相关讨论（信任三要素之三，跨模块打通）

- 从 `squarePosts` 按 tags 关联（同标签即视为相关讨论）；
- 无匹配时区块隐藏（不展示空块）；
- 这打通了「发现 ↔ 广场」：用户从推荐详情看到讨论，点「去广场讨论」进入广场。

### 5. 相关推荐

- 同 `type` 取 3-4 条（排除当前条目）；
- 复用现有 4 列紧凑卡网格（`DiscoveryCard`），点击继续进详情。

### 6. 行动区双出口

- 「前往原平台 →」＝回流（业务闭环的出口，有 `url` 才显示）；
- 「去广场讨论」＝讨论（连接广场，无 `url` 的纯内容也可讨论）。

## 四、数据模型扩展

```ts
export interface DiscoveryItem {
  // …现有字段
  /** 推荐语（发布者原话，详情页重点展示） */
  note?: string;
  /** 推荐人昵称（mock：预置内容可空，发布内容必填） */
  author?: string;
  /** 发布时间（相对时间文案，mock） */
  publishTime?: string;
  /** 社会证明（mock 数值） */
  views?: number;
  likes?: number;
  comments?: number;
}
```

发布弹窗：入口 A/B 提交时 `note = 正文`、`author = "我"`、`publishTime = "刚刚"`、`views/likes/comments = 0`。
