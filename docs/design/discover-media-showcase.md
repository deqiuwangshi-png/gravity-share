## 〇、v2 修订说明

v1 提出"卡片封面 + 详情页展示"，评审后**否决封面方案**：

- ❌ 卡片不做封面——列表保持纯文字 4 列紧凑卡（保住上一轮"高度一致"治理成果，列表只出线索）；
- ✅ 媒体能力**只做在详情页**——列表出线索、详情做消费，富展示发生在用户点进来看的那一步。

数据层仍然只需两个字段（`kind` + `mediaUrl`），但渲染只发生在详情页。

## 一、第一性原理（不变）

平台本质：**分享与推荐平台，打破生态孤岛。**

媒体能帮用户"判断与点击"（✅），但不应"替代原平台承载内容"（⚠️）。边界一条：**引用不托管**。

```
✅ 详情页做：图片直链渲染、视频播放块（点击跳原平台）、文档阅读卡（点击跳原平台）
❌ 引力不做：文件上传、视频托管、文档内嵌预览
```

---

## 二、详情页媒体展示区（内容本体区内，按 `kind` 渲染）

### 形态一 · 图片内容（`kind: "image"`）

```
┌──────────────────────────────┐
│     图片预览（直链图渲染）      │  ← mediaUrl 为图片直链时内联显示大图
└──────────────────────────────┘
完整介绍见下方文字区；点击图片查看原图并跳转原平台。
```

- `mediaUrl` 为图片直链 → 详情页内联大图（`<img>` + 懒加载 + 失败降级）；
- `mediaUrl` 为空 → 显示「图片内容」标记块，点击跳 `url` 查看。

### 形态二 · 视频内容（`kind: "video"`）

```
┌──────────────────────────────┐
│              ▶               │  ← 播放块（不托管、不内嵌 iframe）
│   视频 · 点击到原平台播放       │
└──────────────────────────────┘
```

- 点击播放块 → 跳转 `url`（原平台播放页），浏览器新标签打开；
- 不做内嵌播放器（违背"引用不托管"，且是重功能）。

### 形态三 · 文档内容（`kind: "doc"`）

```
┌──────────────────────────────┐
│ [DOC] 独立开发者知识库（付费专栏）│
│        FlowUs · 打开阅读 →     │
└──────────────────────────────┘
```

- 阅读卡：DOC 图标 + 标题 + 来源平台 + 「打开阅读 →」；
- 点击跳 `url`（原平台阅读/付费），引力不内嵌文档预览；
- 推广型文档卡叠加现有佣金/风险标识（走入口 B 的内容天然带）。

## 三、数据模型扩展（与 v1 相同，渲染位置变化）

```ts
export interface DiscoveryItem {
  // …现有字段
  /** 内容形态：链接 / 视频 / 文档 / 图片（默认 link，发布时按 URL 自动判断） */
  kind?: "link" | "video" | "doc" | "image";
  /** 媒体直链（图片内容用；视频/文档跳 url 即可，可不填） */
  mediaUrl?: string;
}
```

`lib/text.ts` 新增 `judgeKind(url)`：按后缀判断形态（`.pdf/.doc/.md` → 文档，`.mp4/.mov` → 视频，图片后缀 → 图片，其他 → 链接），发布零输入。
