> 版本：v1.1 · 日期：2026-08-21 · 状态：阶段 0 验收完成，已进入 Supabase 数据层阶段
> 上位文档：`ARCHITECTURE.md`（v2.6，已确立边界）· 承接：`docs/ARCHITECTURE-REVIEW.md`（评审报告 v3）
> 一句话：**前端模拟优先，后端与数据库冻结，先把界面布局做好做规范，验收通过前不启动任何后端相关开发。**

## 一、背景与决策

### 1.1 决策声明（已写入 ARCHITECTURE.md §8）

> **前端模拟优先。** 界面布局建设完成并验收前，不启动后端、数据库、认证、API 的任何开发。

理由（避免前期过度复杂化）：
1. 产品处于界面/交互验证期，真后端是本期最大不确定性来源，冻结后团队只盯一件事；
2. mock 数据已足够支撑全部页面的展示与跳转演示；
3. 认证、数据库、异步数据层互相依赖，任何一项提前启动都会牵出其余两项。

## 二、阶段 0：界面布局完善（当前唯一工作范围）

### 2.1 范围（做什么）

| 类别 | 事项 |
|---|---|
| 页面布局 | 三访问区（落地页/认证/应用主页）布局统一、视觉一致、全部路由可达 |
| 链接治理 | 消灭裸 `href="#"`；占位链接统一标记（见 §4 治理规则 R2） |
| 组件治理 | 重复第二次即抽（现状：DiscoveryCard 在 home/recommend 两页重复，待抽） |
| 样式治理 | `app.css`（1,312 行）按组件拆分；颜色只走 globals.css 变量 |
| 数据治理 | 图标方案统一为一种写法；类型收敛到 `types.ts` |
| 文档治理 | README 重写、文档与实现一致、提交自检执行 |

### 2.2 不做（冻结清单，写代码时划红线）

- ❌ 不建 `lib/api.ts`、不写 fetch、不引数据请求库
- ❌ 不写认证/登录态/守卫（含 mock session）
- ❌ 不动数据库、不加后端依赖（Redis、Prisma、ORM 等一律不装）
- ❌ 不把 mock 常量改成异步
- ❌ 不新增分类体系/图标方案（先归一）

### 2.3 验收标准（满足全部才算「界面布局建设完成」）

| # | 标准 | 检验方式 |
|---|---|---|
| V1 | 全站路由可达，无裸 `href="#"` | 全局检索 `href="#"` 结果为 0 |
| V2 | 三访问区布局一致（应用主页共用 AppShell 骨架） | 视觉走查 + 代码核对 |
| V3 | 单文件 CSS ≤ 400 行，色值 100% 走变量 | `wc -l` 检查 + 检索 `#hex` |
| V4 | 组件抽象闭环：同类结构出现 2 次即已抽取 | 代码 review |
| V5 | 文档与实现一致：无「已实现但实际没有」的承诺 | 逐条对照 ARCHITECTURE.md |
| V6 | `pnpm lint` + `pnpm build` 通过 | 命令执行 |

> **V2 补充条款（2026-08-21）**：**阅读/详情型页面（如话题详情 `/square/[id]`）允许单栏聚焦**（仅保留壳布局，去掉右栏）；列表/信息流页面保持两栏一致。壳布局一致是硬约束，内容区按页面职能允许差异化。
>
> 验收通过后：冻结清单中的后端事项**依然冻结**，直到业务方另行确认启动后端（触发条件见 ARCHITECTURE.md §8）。

## 四、治理规则（阶段 0 生效，写入协作约定）

- **R1 文档即契约**：文档承诺必须对应代码事实；代码没有的，文档不许写「已实现」。发现偏差立即二选一：补代码或改文档。
- **R2 链接红线**：禁止提交裸 `href="#"`。占位链接必须二选一——指向真实路由，或渲染为非链接（`<span>`）并加 `data-placeholder` 标记。
- **R3 防膨胀红线**：新增第 3 套分类体系或第 3 种图标方案前，必须先归一（当前已有 4 套分类、3 种图标写法）。
- **R4 提交自检**：提交前过 4 项——① `pnpm lint` 通过；② 无 `href="#"`；③ 无新 `#hex`；④ 无越界（动了冻结清单里的东西要打回）。
- **R5 评审节奏**：每两周一次架构/治理回顾，对照本方案进度；任何「要不要提前接后端」的讨论，只在本回顾上发起，不在日常开发中临时插入。

## 五、演进路径（触发后执行，当前不启动）

```
阶段 0 界面布局完善（现在）──验收 V1-V6 通过──▶ 业务方确认接后端？
                                                        │
                                    ┌───────────────────┴───────────────────┐
                                    │ 是（启动阶段 1）           否（继续冻结，维持现状）
                                    │                             │
                             后端接入：                         重复阶段 0 的治理循环
                             数据访问层设计 · 认证 · 分类归一       （新增页面/组件照规则走）
```

- **阶段 1（接后端）**：届时才做——异步数据访问层（`lib/api.ts`）、认证（proxy 守卫 + 真实 session）、四套分类归一为单一枚举、登录 mock 替换。以上事项在阶段 0 **一律不启动**。
- **阶段 2（规模化）**：组件 > 10 / 页面 > 8 时——components 分子目录、冒烟测试 + CI、可观测性。
