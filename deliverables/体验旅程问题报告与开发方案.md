# 引力 · 用户发布旅程体验问题报告与开发方案

> 基于用户真实走查：发布 → 发现流 → 详情 → 评论 → 个人主页 全链路体验复盘。
> 日期：2026-08-22 · 范围：纯前端 MVP（Supabase 已接库）

---

## 一、旅程复盘

用户登录后从主页【+发布】选择「推荐好东西」，随手发布一段推荐文案 → 文案出现在发现流 → 点击自己的卡片进入详情页 → 在详情页评论区发了一条评论 → 在评论中点击自己头像/昵称进入个人主页 → 检查自己主页「发现」区内容。

全程共暴露 **10 个体验问题**：1 个加载性能、1 个数据刷量漏洞、1 个文案乱码、4 个交互缺失（图标/菜单/头像可点/评论框）、2 个个人主页信息完整度问题、1 个统计展示问题。

---

## 二、问题清单（现象 → 根因 → 修复）

| # | 优先级 | 现象 | 根因 | 修复 |
|---|--------|------|------|------|
| 1 | P1 | 点击卡片进详情页，长时间停在「加载中…」 | 详情页为纯 client 页，首屏要等 5 个查询全部完成才渲染（含全量发现流 + 全量广场流，用于「相关推荐/相关讨论」，不该阻塞首屏）；加载态只是纯文字 | 主体（帖子+点赞态+评论）到齐即渲染；相关区后台补齐并限条数；加载态改骨架屏 |
| 2 | P1 | 互动栏「1 评论、已赞 1、10 浏览」纯文字无图标 | 详情互动栏、广场互动条、列表卡统计全部为纯文本渲染 | 新增统一 SVG 图标（评论/点赞/浏览），详情、广场、列表、评论标题统一带图标 |
| 3 | P1 | 评论区自己头像旁出现「now」奇怪字符，仅在评论区出现 | `formatRelativeTime` 对 1 分钟内的数据返回英文 `"now"`；只有刚发布的评论（自己刚评论）会命中，所以此前从未见过 | 相对时间全量中文化：`刚刚 / X 分钟前 / X 小时前 / X 天前` |
| 4 | P1 | 自己的评论没有水平三点菜单（需 删除/分享/复制） | 评论区没有任何操作菜单组件 | 新增评论操作菜单：本人视角 → 删除（落库+列表刷新，评论计数同步回落）/ 复制 / 分享 |
| 5 | P1 | 他人视角的三点菜单需 举报/分享/复制 | 同上，无他人分支 | 菜单他人分支 → 举报 / 复制 / 分享；举报 MVP 先做前端反馈，后端 reports 表后续接入 |
| 6 | P1 | 点头像无反应，只能点名字才进主页 | `AvatarBox` 纯展示，跳转只绑在 `AuthorLink`（名字）上 | 头像组件支持 `authorId`，头像可点跳 `/profile/[id]`；发现卡/详情头/评论头像/广场/主页帖子卡统一生效 |
| 7 | P1 | 自己一个人看，浏览量却涨到 18（无防刷） | `bump_views` RPC 无任何限制，进详情一次 +1，刷新一次加一次 | 迁移 013：作者本人浏览不计 + 同一用户 30 分钟去重（`view_events` 明细表，客户端无直接权限） |
| 8 | P2 | 评论框太矮，要支持多行（两行），评论区更舒展 | 两处评论框都是单行 `<input type="text">` | 改 `<textarea rows={2}>`：Enter 发送、Shift+Enter 换行，可纵向拉伸，容器同步调优 |
| 9 | P2 | 个人主页「发现」区自己的内容没有三点菜单（需 删除/修改/复制/分享） | 主页帖子卡无任何操作入口 | 帖子卡本人视角新增 ⋯ 菜单：删除（confirm+落库+列表刷新）/ 修改（正文内联编辑落库）/ 复制 / 分享 |
| 10 | P2 | 个人主页「发现」区只有内容，没有赞/评论/浏览数据，很单调 | 帖子卡无统计行 | 帖子卡底部新增统计行（赞/评论/浏览，带图标），与发现卡信息层级对齐 |

## 三、开发方案

### 3.1 前端（本次已实施）

| 模块 | 文件 | 改动 |
|------|------|------|
| 相对时间 | `lib/text.ts` | `formatRelativeTime` 中文化，消灭英文 "now" |
| 查询层 | `lib/queries.ts` | `fetchDiscoveries/fetchSquarePosts` 增加 limit；作者名空值兜底 `safeName` |
| 图标库 | `components/app/common/action-icons.tsx`（新增） | CommentIcon / LikeIcon / ViewIcon / MoreIcon，stroke 极简 SVG，currentColor |
| 头像可点 | `components/app/common/avatar-box.tsx` | 新增 `authorId` 属性，头像可点击跳转主页 |
| 评论菜单 | `components/app/common/comment-menu.tsx`（新增） | 三点菜单：本人 删除/复制/分享，他人 举报/复制/分享；Esc/外点关闭；操作反馈浮层 |
| 广场评论框 | `components/app/square/square-comment-box.tsx` | 单行 input → 两行 textarea，Enter 发送 / Shift+Enter 换行 |
| 广场详情 | `app/(app)/square/[id]/page.tsx` | 评论行挂菜单、头像可点、互动条/标题带图标、取当前用户判本人 |
| 广场互动条 | `components/app/square/square-actions.tsx` | 点赞/浏览带图标 |
| 广场列表卡 | `components/app/square/square-feed.tsx` | 赞/评论/浏览统计带图标 |
| 发现详情 | `app/(app)/discover/[id]/page.tsx` | 首屏拆分（主体先渲染、相关区后台补齐+限条数）、骨架屏、互动栏/评论标题带图标、评论菜单、多行评论框、头像可点 |
| 发现/首页卡 | `components/app/discovery/discovery-card.tsx` | 头像可点 |
| 主页帖子卡 | `components/app/discovery/profile-post.tsx` | 本人 ⋯ 菜单（删除/修改内联编辑/复制/分享）+ 统计行 |
| 主页视图 | `components/app/shell/profile-view.tsx` | 帖子卡透传 isSelf / onChanged |
| 他人主页 | `app/(app)/profile/[id]/page.tsx` | 昵称空值兜底 |
| 样式 | `globals.css` / `detail.css` / `detail-comments.css` / `square.css` / `profile.css` | 菜单浮层、多行评论框、图标对齐、骨架屏、统计行、内联编辑 |

### 3.2 数据库（需在 Supabase SQL Editor 执行）

**`supabase/migrations/013-views-anti-spam.sql`**：

1. 新建 `view_events` 明细表，RLS 全禁 + revoke 客户端权限（只有 RPC 可写）
2. 重写 `bump_views`：**作者本人浏览不计 + 同一用户 30 分钟内只记 1 次**
3. 新增评论 delete 触发器：`comments_count` 同步回落

> 注意：迁移 013 需手动在 Supabase Dashboard → SQL Editor 执行（幂等，可重复执行）。

## 四、遗留项（后续版本）

| 项 | 说明 |
|----|------|
| 举报落库 | 举报目前仅前端反馈（「已收到举报」），需建 `reports` 表 + 管理后台后接入 |
| 评论修改 | 需求只覆盖帖子修改；评论的修改功能未纳入，确认需要再加 |
| 帖子删除的图片清理 | 广场帖带配图，删除帖子时未联动清理 storage 对象（discoveries 无图，暂不受影响） |
| 匿名浏览量 | 未登录不计数（应用内详情需登录，影响面极小） |

## 五、验证方式

1. **构建**：`env -u NODE_OPTIONS pnpm build`（已通过）
2. **数据库**：在 Supabase SQL Editor 执行 `013-views-anti-spam.sql`，按文件底部验证注释自测：
   - 作者本人调用 `bump_views` → views 不变
   - 他人 30 分钟内重复调用 → 只 +1 一次
   - 删除评论 → 对应内容 `comments_count` 减 1
3. **手工走查**：按「旅程复盘」重走一遍，核对 10 项问题全部消失
